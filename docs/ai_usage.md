# AI Usage Log

This document records meaningful AI assistance, including failures and corrections. It is intended to support the required reflection on AI use in the Data Analytics project.

## 2026-09-21 / 2026-09-22 — OJP request construction

**Task:** Build a first OJP 2.0 request for departure data.

**AI contribution:** An initial request structure was proposed.

**What did not work:** The first version used `StopPlaceRef` in the request and returned HTTP 400.

**Correction and validation:** The request was changed to use `siri:StopPointRef` inside `PlaceRef`. The corrected request returned HTTP 200 and valid `StopEventResult` elements.

**Lesson:** XML/API structures generated by AI must be checked against the actual API response and documentation.

## 2026-09-21 — Refactoring collection code

**Task:** Turn the pilot request into a reusable `collect_ojp_station()` function.

**AI contribution:** A reusable function and parsing structure were drafted.

**What did not work:** One refactoring attempt introduced malformed XML/indentation and again caused HTTP 400.

**Correction and validation:** The XML body and indentation were repaired, then tested against Zürich HB and Bern. The function returned 30 connections and saved the raw/parsed data correctly.

**Lesson:** Refactoring can introduce failures even when the original prototype works. The API status code and saved raw response are essential validation tools.

## 2026-09-21 — Missing real-time values

**Task:** Calculate delay from scheduled and estimated departure timestamps.

**AI contribution:** Discussion of how missing `EstimatedTime` values should be handled.

**Risk identified:** Filling missing real-time values with scheduled time would incorrectly create a zero-delay observation.

**Decision:** Missing `EstimatedTime` remains missing (`NaN`). `predicted_delay_minutes` is only calculated where a real-time estimate exists.

**Lesson:** Convenient imputation can change the meaning of the target variable and create false observations.

## 2026-09-22 — Delay semantics

**Task:** Define the delay variable for analysis.

**AI contribution:** Review of the OJP fields and proposed terminology.

**Decision:** `EstimatedTime` is treated as a real-time estimate. The derived value is therefore named `predicted_delay_minutes`, not `actual_delay_minutes`.

**Lesson:** Variable names must reflect what the source actually measures.

## 2026-09-22 — Multi-station collector

**Task:** Collect data from 8 regions with rail and local-public-transport stops.

**AI contribution:** A multi-station Python collector was drafted with raw-response storage, error handling and combined snapshots.

**Validation:** The script was syntax-tested and parser-tested before use. The live test then returned 479 observations from 16/16 configured stops with zero failed stations.

**Lesson:** AI-generated code should be validated in layers: syntax, controlled parser tests and then live API execution.

## 2026-09-22 — MeteoSwiss collector

**Task:** Add the second data source for weather.

**AI contribution:** Selection of nearby SwissMetNet stations, MeteoSwiss parameter identifiers and a collector for current 10-minute measurements.

**Validation approach:** The code is designed from the official MeteoSwiss Open Data file structure and parameter documentation. A synthetic CSV parser test was performed before committing. A live repository-side test is still required after pulling the commit.

**Lesson:** Source documentation should determine timestamp timezone, units and field semantics rather than assumptions.
